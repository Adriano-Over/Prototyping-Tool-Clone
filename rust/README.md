# Rust migration workspace

This workspace is an incremental migration alongside the current Forma editor; the Rust crate is not yet connected to the running editor. The `forma-core` crate validates and losslessly retains legacy project envelopes, and projects simple legacy component trees into typed pages and nodes. It supports ordered multiple frames, frame metadata retention, and CSS 2D matrix conversion as described below, while unsupported visual styling and layout are reported or rejected. It also provides atomic undo/redo history for generic object-property and ordered-array changes. The typed model serializes pages and nodes with hierarchy and geometry validation, preserves unknown fields, and retains unknown node kinds without rendering them. A complete project format, feature-specific design commands and rendering, styling parity, editor integration, storage, application UI, and a server remain to be implemented.

An experimental project container holds validated pages, identity, revision, unknown project fields, and an optional original legacy envelope. `project_simple_pages` can project simple legacy component trees, including pages with multiple frames, while retaining the entire original envelope. Frame metadata is preserved on each converted frame root but is not interpreted. Multi-frame pages receive a synthetic zero-sized root and a warning. The converter resolves ID-based CSS rules and inline overrides at the default 1400px workspace width, then maps basic absolute geometry, CSS 2D `matrix(...)`, `rotate(...)`, `translate(...)`, `scale(...)`, and `skew(...)` transforms, and a constrained subset of CSS flex layout. Flex row/column containers support fixed or intrinsic main/cross sizing, pixel gaps and padding, main-axis justification, cross-axis alignment, and basic grow/basis sizing. Flex wrapping, CSS grid, shrinking when items overflow, and unresolved intrinsic sizing are rejected instead of guessed. Relative-positioned children are accepted only as flex items; normal-flow positioning outside flex is not resolved and must not be treated as exact. Class selectors, 3D or unsupported CSS transform syntax, and non-pixel geometry are also rejected. Other visual styles remain in the source and are reported. It is not a complete converter or a finalized on-disk project format.

The original legacy envelope remains preserved after native scene edits. `Project::edit_pages` stages and validates the edit, increments the project revision, and leaves the original snapshot tagged with its capture revision, so `legacy_snapshot_is_current()` turns false without silently deleting source data. `ProjectHistory` applies reversible commands only within `/pages`, validates the staged project before commit, and advances revisions during undo and redo as well. Its typed `set_node_transform` operation targets nodes by page and node ID; `reorder_child` changes a parent's back-to-front order without changing node geometry. Direct project fields are crate-private; callers use read-only accessors and validated edit/history APIs. Old serialized projects without a snapshot revision are conservatively treated as stale.

Variable aliases can be resolved across collections and selected modes, with errors for cycles, missing values, and type mismatches. An initial adapter reads explicitly defined variables from legacy project metadata and retains authored mode order. Legacy untyped `modes` entries, numeric strings, and other unsupported values are not converted; broader parity checks and editor integration remain necessary. The original project JSON remains available unchanged.

From this directory, run `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, and `cargo test --workspace --locked`. From the repository root, `node scripts/test-rust-js-parity.mjs` compares the Rust converter's retained editor payload with JavaScript project normalization on the shared real-derived flex fixture. The tests compare JSON values, not byte-for-byte serialization.
