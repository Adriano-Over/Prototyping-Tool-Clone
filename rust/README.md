# Rust migration workspace

This workspace is an incremental migration alongside the current Forma editor; the Rust crate is not yet connected to the running editor. The `forma-core` crate validates and losslessly retains legacy project envelopes, and projects simple legacy component trees into typed pages and nodes. It supports ordered multiple frames, frame metadata retention, and CSS 2D matrix conversion as described below, while unsupported visual styling and layout are reported or rejected. It also provides atomic undo/redo history for generic object-property and ordered-array changes. The typed model serializes pages and nodes with hierarchy and geometry validation, preserves unknown fields, and retains unknown node kinds without rendering them. A complete project format, feature-specific design commands and rendering, styling parity, editor integration, storage, application UI, and a server remain to be implemented.

An experimental project container holds validated pages, identity, revision, unknown project fields, and an optional original legacy envelope. `project_simple_pages` can project simple legacy component trees, including pages with multiple frames, while retaining the entire original envelope. Frame metadata is preserved on each converted frame root but is not interpreted. Multi-frame pages receive a synthetic zero-sized root and a warning. The converter also reports unconverted visual styles and missing dimensions; relative layouts, 3D or unsupported CSS transform syntax, and non-pixel geometry are rejected. CSS 2D `matrix(a,b,c,d,e,f)` transforms are mapped to affine transforms, including CSS transform-origin positioning for pixel and percentage origins. It is not a complete converter or a finalized on-disk project format.

Variable aliases can be resolved across collections and selected modes, with errors for cycles, missing values, and type mismatches. An initial adapter reads explicitly defined variables from legacy project metadata and retains authored mode order. Legacy untyped `modes` entries, numeric strings, and other unsupported values are not converted; broader parity checks and editor integration remain necessary. The original project JSON remains available unchanged.

From this directory, run `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, and `cargo test --workspace --locked`. The fixture files are synthetic; the tests compare JSON values, not byte-for-byte serialization.
